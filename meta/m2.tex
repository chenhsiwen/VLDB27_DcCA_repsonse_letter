\paragraph{Meta-2 (Discuss evidence availability and failure cases).}

\begin{itemize}[leftmargin=1.2em, itemsep=1pt, topsep=2pt]
\item \textit{``\dots the revision must discuss what happens when no feasible or useful counterfactuals are present. For example, empty-set behavior, fallback strategies, and trade-offs compared with model-centric or generative counterfactual approaches.''}
\end{itemize}
\smallskip

\noindent\textbf{Response.}
\hw{Evidence availability is fundamental to a data-centric paradigm, and DcCA handles it explicitly. We answer the three parts directly.

\textbf{When no feasible counterfactual exists, DcCA returns the empty set.} By Eq.~(1), an instance is admissible if and only if $\omega(\mathbf{x}_q,\mathbf{x})<\infty$; when $\omega(q)=\varnothing$, no observed instance satisfies both the opposite-outcome predicate and admissibility. Returning the empty set is an informative, verifiable outcome, not a failure: it \emph{certifies} infeasibility under the current $\omega$. This is an epistemic advantage---generative and model-centric methods always synthesize a candidate and cannot make this statement.

\textbf{Fallback is graded.} When the feasible set is empty or has fewer than $k$ instances, DcCA (i) progressively relaxes user-specified soft constraints (e.g., raises the cost budget or relaxes non-essential preferences) and reports the \emph{minimal} relaxation that restores feasibility, and (ii) if no data-grounded answer is found, optionally hands off to a model-centric/generative method as an explicitly flagged, unverified fallback. This keeps evidence-supported answers clearly separated from synthesized ones.

\textbf{Trade-offs are complementary, not competing.} Data-centric analysis guarantees realism, feasibility, provenance, and verifiability because every answer is an observed instance, but its coverage is bounded by $\mathcal{D}$. Model-centric/generative methods always produce an answer but the result may not correspond to any observed object or feasible intervention. Our new validity study makes the coverage effect concrete: in Table~\ref{tab:validity}, DcCA returns feasible, in-distribution counterfactuals whenever a matching instance exists, while for $16\%$ of queries no observed instance shares the query's immutable profile---exactly the empty-set/fallback regime. Coverage is itself measurable and grows with $\mathcal{D}$. We added a new paragraph, ``Evidence availability and failure behavior,'' to Section~2.}
