\paragraph{Meta-2 (Discuss evidence availability and failure cases).}

\begin{itemize}[leftmargin=1.2em, itemsep=1pt, topsep=2pt]
\item \textit{``\dots the revision must discuss what happens when no feasible or useful counterfactuals are present. For example, empty-set behavior, fallback strategies, and trade-offs compared with model-centric or generative counterfactual approaches.''}
\end{itemize}
\smallskip

\noindent\textbf{Response.}
Evidence availability is fundamental to a data-centric paradigm, and DcCA handles it explicitly. We answer the three parts directly.

\textbf{When no feasible counterfactual exists, DcCA returns the empty set.} By Eq.~(1), an instance is admissible if and only if $\omega(\mathbf{x}_q,\mathbf{x})<\infty$; when $\omega(q)=\varnothing$, no observed instance satisfies both the opposite-outcome predicate and admissibility. Returning the empty set is an informative, verifiable outcome, not a failure: it \emph{certifies} infeasibility under the current $\omega$. This is an epistemic advantage---generative and model-centric methods always synthesize a candidate and cannot make this statement.

\textbf{Fallback stays data-centric.} When the feasible set is empty or has fewer than $k$ instances, DcCA returns the certified empty set or a partial set with provenance; where the specification permits, it also progressively relaxes user-specified \emph{soft} constraints (e.g., raises the cost budget or relaxes non-essential preferences) and reports the \emph{minimal} relaxation that restores feasibility. Every such answer remains grounded in observed data: DcCA does not depend on a generative method as a crutch, and the empty set is itself an informative, verifiable answer.

\textbf{Trade-offs are complementary, not competing.} Data-centric and model-centric analysis \emph{answer different questions rather than serving as fallbacks for one another}: the former asks which feasible alternatives are supported by the observed data---guaranteeing realism, feasibility, provenance, and verifiability, though bounded by the coverage of $\mathcal{D}$---while the latter asks what a predictive model would produce, always returning an answer that may correspond to no observed object or feasible intervention. Our new validity study makes the coverage effect concrete: in Table~\ref{tab:validity}, DcCA returns feasible, in-distribution counterfactuals whenever a matching instance exists, while for $16\%$ of queries no observed instance shares the query's immutable profile---exactly the empty-set regime. Coverage is itself measurable and grows with $\mathcal{D}$. We added a new paragraph, ``Evidence availability and query semantics,'' to Section~2.

\noindent\emph{Revision to Section~2 (new paragraph ``Evidence availability and query semantics''):}
\begin{quote}
{\color{blue}\textbf{Evidence availability and query semantics.}
Data-centric counterfactual querying operates over observed data, so its answers are bounded by the evidence in $\mathcal D$. If $\omega(q)=\emptyset$, no feasible outcome-changing instance satisfies the specified constraints, and the correct answer is the empty set. Rather than indicating failure, the empty set certifies that no evidence-supported counterfactual exists under $\omega$. Likewise, if $0<|\omega(q)|<k$, the query returns all feasible counterfactuals together with their provenance. In both cases, the result faithfully reflects the available evidence.

This evidence-based semantics distinguishes data-centric from model-centric and generative counterfactual analysis. Data-centric querying asks \emph{``What feasible alternatives are supported by the observed data?''} and emphasizes realism, feasibility, provenance, and verifiability. Model-centric methods instead ask \emph{``What alternative would a predictive model produce?''} and can always synthesize a counterfactual without guaranteeing that it is observed or feasible. The two paradigms therefore answer different questions rather than serving as fallbacks for one another. As $\mathcal D$ grows, the coverage of data-centric counterfactual querying naturally increases while preserving its evidence-based semantics.}
\end{quote}
